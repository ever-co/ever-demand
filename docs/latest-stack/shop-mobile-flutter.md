# Flutter shop app (`packages/shop-mobile-flutter`): latest-stack lane notes

The Flutter app was a 2.8k-line static skeleton (Dart 2.17, no backend). It is now a full client of
the Ever Demand API with the feature set of `packages/shop-mobile-ionic`, built from the shop-mobile
feature inventory (`docs/latest-stack/shop-mobile-features.md` on `feat/latest-stack-shop-mobile`).

## Architecture

```
lib/
  main.dart, app.dart             bootstrap, MaterialApp.router, locale, connection watcher
  config/app_config.dart          every --dart-define (names and defaults of scripts/env.ts)
  core/                           theme (Ionic colours), l10n helpers, product locale, formatting
  data/models/                    Order (status rules of packages/common), Warehouse, Product…, Country table
  data/store/                     AppStore: the Ionic Store, same localStorage keys, paying set in memory
  data/network/pyro/              socket.io pyro RPC: PyroRouter.run / observe, PyroClient (one namespace per router)
  data/network/graphql/           documents (verbatim from the Ionic services) + GraphQLService
  data/network/http_services.dart server check, maintenance, getLocationByIP
  data/repositories/              ShopApi (typed routers, exact event names and args), products,
                                  merchants, orders, location
  services/                       startup, session (isLogged), invite, order flow, payment controller
  routing/app_router.dart         go_router routes + the Ionic guards
  features/<page>/                screens (startup, invite, products, order, orders_history,
                                  merchants, language, info, errors)
  widgets/                        drawer, order card, dialogs, badges, common
  platform/platform_services.dart dialer, connectivity, Stripe card tokenizer (interfaces + impls)
  l10n/                           ARB (generated from the Ionic JSON) + gen-l10n output in l10n/gen
```

**Pyro RPC** (`lib/data/network/pyro`) mirrors `packages/common-angular/src/lib/router` and the
server in `packages/core/src/@pyro/io`: one socket.io namespace per router
(`${SERVICES_ENDPOINT}/<router>`, websocket transport, manual reconnect after 1 s), one-shot calls as
`emit(method, ...args, ack)` with `ack(err, res)`, errors rebuilt from `{ __isError__, name, message }`,
observable calls as `emit(method, ...args, callId)` + `${callId}_subscribe(sid)` →
`${sid}_next|_error`, `${sid}_unsubscribe` on cancel. A call in flight when the socket drops fails
with `SocketDisconnectedError` (fleet fix). Differences from the Angular client, on purpose:
observables re-subscribe after a reconnect (the server drops subscriptions with the socket; the
Angular `exhaustMap` never re-subscribes), and the server's complete event (`_${sid}_complete`, with
the leading underscore) is handled. The observable's `onCancel` is synchronous: `Stream.first` waits
for a returned cancel future, and a broadcast subscription's cancel future belongs to the root zone,
so an `async` `onCancel` that awaited it hung every `.first` under `testWidgets` fake time.

**GraphQL**: queries only, `fetchPolicy: networkOnly`, `errorPolicy: all`, `authorization` header from
`token`, subscriptions routed to graphql-ws (`GraphQLProtocol.graphqlTransportWs`). No subscription is
used, as in the Ionic app. The product feed's `watchQuery` + `pollInterval: 2000` is a 2 s timer per
loaded page that only updates the sold-out flags.

## Configuration (`--dart-define`)

Same names and defaults as `packages/shop-mobile-ionic/scripts/env.ts`: `GQL_ENDPOINT`
(`http://localhost:8443/graphql`), `GQL_SUBSCRIPTIONS_ENDPOINT` (`ws://localhost:2086/subscriptions`),
`SERVICES_ENDPOINT` (`http://localhost:5500`), `PRODUCTS_VIEW_TYPE` (`slides`|`list`),
`ORDER_INFO_TYPE` (`page`|`popup`), `DEFAULT_LANGUAGE`, `DEFAULT_LOCALE`, `DELIVERY_TIME_MIN/MAX`,
`SUPPORT_NUMBER`, `STRIPE_PUBLISHABLE_KEY`, `DEFAULT_LATITUDE/LONGITUDE` (Sofia; set them empty to use
the device GPS), `FAKE_UUID`, `FAKE_INVITE_*` (code 8321), `SETTINGS_APP_TYPE`,
`SETTINGS_MAINTENANCE_API_URL`, `MERCHANT_IDS` (comma list), `SHOPPING_CART`, `COMPANY_NAME`,
`PRODUCTION`. Flutter-only: `KEEP_LOCALHOST` (on Android `localhost`/`127.0.0.1` become `10.0.2.2`, the
emulator's host, unless this is `true`), `MAPS_ENABLED`, `MAP_TILE_URL`.

```sh
flutter run --dart-define=STRIPE_PUBLISHABLE_KEY=pk_test_... \
            --dart-define=SERVICES_ENDPOINT=http://192.168.1.10:5500 \
            --dart-define=GQL_ENDPOINT=http://192.168.1.10:8443/graphql
```

## Run, test, build (Docker, no local Flutter)

```sh
cd packages/shop-mobile-flutter
docker build -t ever-demand-flutter:3.50.1 tool/docker     # once (the script does it when missing)
tool/docker-test.sh                                        # analyze test integration build-web build-apk
tool/docker-test.sh analyze test                           # some steps
```

The script mounts the repo read-only, copies the package (and the core GraphQL schema for the schema
test) into the container, keeps caches in the named volumes `ever-flutter-pub-cache`,
`ever-flutter-gradle` and `ever-flutter-android-sdk`, caps Gradle at 2.5 GB heap, and writes logs and
artifacts to `tool/out/` (git-ignored): `analyze.txt`, `test.txt`, `integration.txt`,
`build-web.txt`, `build-apk.txt`, `web.tar.gz`, `app-debug.apk`.

Regenerate the ARB files after the Ionic JSON changes:
`dart tool/ionic_i18n_to_arb.dart` (then `flutter gen-l10n`, or any `flutter` build / test).

## Decisions and differences from the Ionic app

- **New card entry**: the Ionic app opens the legacy Stripe Checkout popup (`checkout.js`) to get a card
  token and the email. Checkout does not exist for Flutter, so the app shows its own sheet (email +
  flutter_stripe `CardField`) and gets the same card token with `Stripe.instance.createToken`; then
  the calls are the same: `user.updateEmail` → `user.addPaymentMethod(token)` →
  `order.payWithStripe(orderId, cardId, currency)` → `order.confirm`. Without
  `STRIPE_PUBLISHABLE_KEY` the card buttons tell "Card payments are not set up in this app" instead of
  throwing. The web build loads Stripe.js in `web/index.html`.
- **Maps**: Google Maps JS (needs a key, and with no network to Google the Ionic app never starts) is
  replaced by flutter_map on OpenStreetMap tiles with markers for customer, merchant and carrier and a
  carrier → customer line (no Google Directions route). The invite-by-location Google geocoder fallbacks
  are not ported: reverse geocoding uses the API's ArcGIS router only, and an invite request uses the
  device (or default) coordinates, the Ionic app's second choice.
- **Popup mode** (`ORDER_INFO_TYPE=popup`) shows the same tracking views in a full-screen dialog; the
  card sheet opens on top of it, so the "open the order modal once per Checkout session" rule holds by
  construction.
- **Material 3 + material_ui**: the app imports `package:material_ui` (Flutter 3.47 deprecated the SDK
  Material library). flutter_map, mobile_scanner, barcode_widget and flutter_widget_from_html_core still
  import the old library; they only read `Theme.of` there and fall back to its defaults, so no
  `MaterialUiCompatibilityBridge` (itself deprecated) is needed.
- Fixed Ionic quirks (inventory "(quirk)" marks): the stored language now wins over
  `DEFAULT_LANGUAGE` (fleet T-2805); the server check clears `serverConnection` on success; the
  order page no longer clears the open order when the customer leaves it from the menu; the
  `NOT_PAID_NOTE` shows only for unpaid orders; search "View more" shows when there are more; the
  discount is computed without the float artefact (8 of 10 = 20 %, the Ionic code shows 19 %); pyro
  observables re-subscribe after a reconnect. Kept quirks: the Store menu group (never shown), the
  "Call for details" text with no action, the social buttons with no action, history rows can only
  comment / remove when the server sends order-product ids.
- Android: `MainActivity` is a `FlutterFragmentActivity` and the launch / normal themes use
  `Theme.MaterialComponents` (flutter_stripe needs both); INTERNET, network state, location and camera
  permissions; `<queries>` for `tel:` and `https`. iOS: location and camera usage descriptions,
  `LSApplicationQueriesSchemes`. The application id stays `com.example.shop_flutter_mobile` (the Cordova
  app is `co.ever.customer`); pick the store id before publishing.

## Backend operations

No schema or router change is needed: every GraphQL document validates against
`packages/core/src/graphql` (unit test), and every router method is an existing pyro listener.
Nothing in this lane edits `packages/core`.
